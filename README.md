# CY — 光伏智能制造项目（设备端增配 × 产线 Agent）

> 状态：规划阶段 v0.4（2026-10-21）　语言：中文　“良率”＝yield，“效率”＝cell efficiency，另含各类缺陷

## 1. 一句话目标

产线客户遇到问题（良率下降、效率下降、各类缺陷）或设备报警时，由光伏专业 Agent 给出分步排查与维修建议：

- **报警驱动**：设备报警 → 推送设备号、报警信息、文字维修建议给客户设备部门（**不发图纸**）；客户可拍照反馈，Agent 分析照片并指出可疑零部件。
- **信号驱动（新增）**：Agent 读取设备信号（例如 CVD 的 leak check 数据），判断慢漏风险，或在 leak check 失败时判断可能原因（详见 `docs/08`）。
- **对话排障**：客户描述问题 → Agent 引导补充文字 / 图片 / 参数 → 排查建议 → 仍无法解决则转人工。

同时在设备端补齐 APC / FDC / EAP（及 MES 接口）能力，让 Agent 从“向客户要数据”逐步升级为“直接读设备数据”。

## 2. 首发范围（v0.2 确认）

- **设备**：光伏干法设备——LPCVD、boron diffusion、POCl3 diffusion、oxidation、laser opening。先做 **1 类垂直切片**（建议 boron diffusion），再复制到其余四类。
- **全线能力**：你们有覆盖湿法、金属化等的全线工艺优化 know-how 和工艺工程师。V1 中作为**因果知识**使用，不单独为这些工序做设备对话。
- **客户**：东南亚 / 欧洲 / 美国，需多语言、跨时区转人工、分地区合规。
- **算力**：客户机房可放 GPU 服务器，边缘自托管可行。

## 3. 两条主线

| 主线 | 内容 | 价值 | 节奏 |
|---|---|---|---|
| A 设备端增配 | 报警通道 → 采集 → FDC → APC → EAP / MES 接口 | 增配收入；Agent 的自动数据源 | 长（硬件 + 现场验证） |
| B 产线 Agent | 知识库 + LLM 编排 + 工具 + 报警推送 + 转人工 | 降低售后成本；沉淀知识壁垒 | 短（约 3–4 个月内部可用） |

两条线并行，但**互不阻塞**。唯一提前的衔接点：设备端的**报警通道**要早做（见 `docs/07`）。

## 4. 八个核心设计决定

1. **区分“数据”与“知识”。** 客户原始数据不出厂；向上流动的只有经授权、脱敏的 case card；向下流动的是签名的知识包。中心化的是知识，不是客户数据。
2. **先内部、后客户。** Agent v1 先做成你们自己售后工程师的 copilot。
3. **LLM 是“调度员”，不是“专家大脑”。** 负责提问、整理、格式化；事实来自 playbook / case card，必须引用来源，没有来源就转人工。
4. **售后记录是核心资产，论文是背景资料。**
5. **设备端不与 Agent 绑死，但数据字典先对齐。**
6. **确定性优先。** 报警 → playbook → 推送走确定性路径，LLM 只润色；LLM 不可用时仍推送模板消息。
7. **自托管 + 数据分级 + 权限在检索层。** 客户数据不发往云端 LLM，不进模型权重（见 `docs/06`）。图纸不下发到客户节点。
8. **数值判断由确定性代码完成，LLM 不做数值推断。** 阈值与规格取自设备 recipe，Agent 不建议放宽规格或跳过检查（见 `docs/08`）。

## 6. 已确认信息与待确认问题

**已确认**：干法设备范围、全线工艺 know-how、客户分布（SEA / EU / US）、客户可放 GPU、良率 / 效率 / 缺陷定义、需要报警驱动推送；设备控制为 **PLC**；图纸为 **PDF 且有版本管理，仅内部使用，不发给客户**；推送渠道**邮件为主，WhatsApp 作可选提醒通道**（见 `docs/07`）；售后数据为 **Excel / PDF / 文字**。

**待确认（会改变计划）**

1. **PLC 品牌与型号**：是否带上位机 / HMI 软件？报警文本在 PLC 里还是在上位机里？现有报警表能否导出？
2. **图纸与设备台账**：是否有“某台设备（序列号）↔ 某版图纸”的台账（含改造记录）？图纸 PDF 是文字版还是扫描件？（图纸仅内部使用，用来生成件号和位置描述）
3. **售后数据**：数量？Excel 列是否统一？PDF 是文字版还是扫描件？文字来自工单、邮件还是聊天？是否记录“最终是否解决”？
4. **客户合同**：现有数据使用 / 保密条款；各地区（SEA / EU / US）合规要求。
5. **团队与预算**：核心团队几人？能否有 1–2 位专家每周约 2 小时。
6. **客户 GPU 规格**：型号 / 显存，或你们打算的标准配置。
7. **WhatsApp 使用方式**：推给个人还是群组？客户 IT 是否允许？客户是否愿意 opt-in？
8. **Leak check 数据**：PLC / 上位机保存的是原始压力曲线，还是只有最终结果？采样频率？历史 leak check 失败有多少次，失败后怎么处理的有没有记录？
9. **零部件照片库**：售后里有没有带标签的故障零件照片（以及大概数量）？
10. **照片分析放哪里**：`docs/07` 第 9 节的方案 A（客户节点放零部件参考包，本地分析）、B（照片传回你们环境）还是 C（转人工看图）？
